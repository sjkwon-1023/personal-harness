# 전체 청크 계획

메인은 현재 세션이다. 외부 모델 위임은 `~/.config/coding-harness/pane/PANE.md`를 따른다.

원문 요구, 목적, 확정 제약, 기존 계약, 미해결 질문, 확인한 파일, 실제 검증 수단을 브리프로 작성한다.
정해지지 않은 아키텍처를 메인이 먼저 정해 planner에게 추인받지 않는다. 이미 완성된 계획은 다시 쓰지 않는다.

1. 계획 작성: `--role plan`으로 요청한다. 모델은 사용자 지정이 없으면 `routing.json`의 난이도별 `planner`를 쓴다.
2. 계획 검증: 검증 모델이 정해졌으면 원문 요구, 완성 계획, 코드 경로를 새 세션에 `--role plan-review`로 보낸다.
   기본은 한 번이고, 설계가 크게 바뀌었을 때만 바뀐 부분을 다시 검증한다.
3. 메인이 계획에 `roles/planner.md`의 항목이 빠지지 않았는지 확인하고, 핵심 전제와 findings를 코드로 직접 대조해
   채택·기각 근거를 남긴다. 계획과 진행 상태는 실행 기록에, 설계 문서는 레포 문서 규칙에 따라 둔다.

계획만 승인됐으면 결과를 보고하고 멈춘다. 구현도 승인됐으면 다시 묻지 않고 dispatch-plan의 청크 실행으로 넘어간다.
