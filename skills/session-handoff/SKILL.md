# Session Handoff

새 세션이 바로 실행할 수 있는 작업 지시 프롬프트를 만든다. 지난 세션의 회고가 아니라 확정된 맥락 위에 세운 다음 작업 지시다.

## 자료 모으기

- 대화에서 확정된 계획과 결정을 중심으로 추린다. `docs/plans/<feature>-plan.md`(검토 기록은 `docs/reviews/`)가 있으면
  1차 자료로 쓰고 경로를 프롬프트에 넣는다.
- 필요하면 `git status`, `git diff --stat`, 관련 파일 정도만 가볍게 확인한다. 코드를 바꾸거나 파괴적 명령을 실행하지 않는다.
- dispatch-plan 진행 중이면 `~/.config/coding-harness/skills/dispatch-plan/chunks.md`의 재개 항목을 넣고,
  새 세션이 그 재개 절차로 이어가도록 지시한다. `sent`·`received`·`reported`만으로 청크를 인수했다고 쓰지 않는다.

## 출력

한국어로 쓰고 코드·식별자·명령은 원문을 유지한다. 두 부분으로 내고 같은 내용을 두 곳에 쓰지 않는다.

**1. 검수 노트 (3~6줄)** — 붙여넣기 전에 사용자가 확인할 메타 정보만 적는다.
- 근거 소스: 설계 문서 경로, 대화의 확정 결정, 확인한 파일
- 확인 필요: 불확실한 가정이나 빠진 전제 (없으면 "없음")
- 뺀 것: 의도적으로 제외한 내용과 이유 (있을 때만)

**2. 붙여넣을 프롬프트** — 추가 설명 없이 그대로 쓸 수 있게 완결되게 쓴다. 파일명·명령·계약·완료 기준을 모호한 요약보다
우선하고, 중요한 맥락은 지나치게 줄이지 않되 관련 없는 대화는 뺀다.

```text
아래는 [프로젝트/기능]에 대해 확정된 맥락이야. 이걸 기준으로 다음 작업을 진행해줘.

## 맥락
[프로젝트 개요, 확정된 계획·결정·제약·컨벤션, 중요하면 버린 대안과 이유, 설계 문서 경로]

## 현재 코드 상태
[만들어졌거나 바뀐 파일, 동작/미완성. 구현 전이면 "구현 전 — 코드 변경 없음"]

## 진행할 작업
[우선순위 있는 명령형 지시, 완료 기준, 먼저 볼 파일·명령]

## 주의사항
[지켜야 할 제약·선호, 깨지기 쉬운 부분, 이미 실패한 접근]

## 작업 방식
- 시작 전에 관련 파일을 먼저 확인해줘.
- 위 확정 결정은 바꾸지 말고 따라줘.
- 불확실한 부분은 추측하지 말고 "확인 필요"로 표시해줘.
- 끝나면 바뀐 파일과 이유를 간단히 정리해줘.
```
