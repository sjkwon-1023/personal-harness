# Dispatch Plan

메인은 이 스킬을 호출한 현재 세션이다. 오케스트레이션을 다른 CLI로 넘기지 않는다.
계획만 요청했으면 계획까지만 하고, 이미 승인된 실행은 다시 묻지 않는다.
외부 모델 위임은 `~/.config/coding-harness/pane/PANE.md`를 따른다.

## 메인의 책임

- 사용자 요구, 승인 범위, 전체 계획, 모델 선택, pane 소유권, 진행 상태를 유지한다.
- 위임할 때 역할, 소유 파일, 공유 계약, 완료 조건, 검증 명령, 결과 경로를 브리프에 명시한다.
- 실제 코드·diff·게이트 로그로 청크를 인수하고, 인수 전에는 다음 청크를 보내지 않는다.

## 난이도와 역할

난이도별 기본 역할 조합은 `~/.config/coding-harness/pane/routing.json`에 있다. 사용자가 지정한 CLI·모델·effort·pane이
우선하고, 사용자가 지정한 최종 검수자는 기본 검수자를 대체한다.

- `simple`: 메인이 직접 계획·구현·검수한다.
- `medium`: 외부 모델이 계획·구현·최종 검수를 맡는다.
- `hard`: 여기에 독립 계획 검증과 복수 최종 검수를 더한다.

난이도는 변경량과 함께 설계 불확실성·의존성·보안·데이터·외부 계약 영향으로 정하고, 적용 경로를 사용자에게 짧게 알린다.

## 순서

1. 요청, 확정 계획, 코드 상태, 승인 범위를 확인하고 실행 기록을 `~/.local/share/coding-harness/runs/<task-id>/`에 만든다. 이어서 하는 작업은 기존 경로를 쓴다.
2. 실행 가능한 전체 계획이 없으면 `~/.config/coding-harness/skills/review-plan/SKILL.md`를 수행한다.
   계획이 이미 있으면 다시 쓰지 않고 요구 대응, 의존성, 소유 파일, 계약, 완료 조건, 검증 명령의 누락만 확인한다.
3. 구현이 승인됐으면 같은 폴더의 `chunks.md`에 따라 청크를 순서대로 맡기고 하나씩 인수한다.
4. 모든 청크를 인수하면 메인이 통합 게이트를 직접 실행한 뒤 최종 검수를 받는다.
5. findings를 실제 코드로 확인하고, 고쳤다면 관련 게이트와 영향받은 검수를 새 세션으로 다시 받는다.
   마지막 수정 이후 필수 게이트와 검수가 모두 통과해야 전역 규칙에 따라 커밋·push·PR을 진행한다.

## 최종 검수

`simple`은 메인 검수로 끝내되 사용자가 검수자를 지정했으면 따른다. 그 외에는 검수 모델마다 새 세션에 `--role review`로 요청한다.

- 브리프에는 원문 요구, 전체 계획, 공유 계약, base SHA와 HEAD, 누적 tracked diff, untracked 파일 경로,
  기존 사용자 변경과의 구분, 게이트 명령·종료 코드·로그, 남은 실패와 미실행 검증을 넣는다.
- 여러 검수자에게 같은 자료를 주고 결과 경로를 나눈다. 서로의 findings나 메인의 평가는 알려주지 않는다.
- 호출 실패, 빈 결과, 끝나지 않은 필수 검수는 통과가 아니다. 중복 findings를 합치고 채택·기각 근거를 남긴다.

메인 세션을 바꿔야 할 때만 session-handoff를 쓰고, `chunks.md`의 재개 항목을 넘긴다.
